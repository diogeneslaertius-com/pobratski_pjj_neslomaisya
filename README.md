# Парсер адресов Казахстана

Правила + справочник. Без ML, без сети: работает офлайн.

## Запуск в Docker (основной способ для сдачи)

```
python tools/extract_osm.py kazakhstan-261015.osm.pbf data/reference.sqlite   # один раз (сеть не нужна)
docker compose up --build
```
- API: http://localhost:8000 — `POST /parse_batch` (список записей -> список ответов), `POST /parse` (одна запись; список тоже принимает), `POST /parse/explain` (+источники и подсказки), `GET /health`, документация `/docs`
- UI:  http://localhost:8501
- Справочник `data/reference.sqlite` копируется В ОБРАЗ; в работе сеть не нужна.
- Сборка падает, если справочника нет (чтобы не сдать игрушечный seed). Для отладки:
  `docker compose build --build-arg ALLOW_SEED=1`.
- Пример запроса:
  ```
  curl -X POST localhost:8000/parse_batch -H "Content-Type: application/json" \
       -d '[{"id":"1","raw_address":"Ул .Курильская 9 кв 1"}]'
  ```
- ВАЖНО про офлайн: `docker compose up --build` во время сборки качает пакеты (pip), без сети она упадёт.
  Образ надо собрать заранее, пока сеть есть, и везти готовым:
  `docker save kz-address-parser | gzip > image.tar.gz`; на целевой машине `docker load -i image.tar.gz`,
  затем `docker compose up -d` (без `--build`: образ уже есть, пересборка не нужна).
- Замеры: `python tools/bench.py -n 1000 --url http://localhost:8000` (1000 записей), старт: `time docker compose up -d --wait`.
- Мои результаты HTTP: 1000 записей за 1.23с    
- real 0m8.941s, user0m0.573s Docker (0.5ms)
- Статус: файлы Docker проверены только по синтаксису (`docker compose config`); образ собирался мной (16 команда Рысбек) несколько раз, и работает в стабильном состоянии
  Первую сборку
  надо провести и замерить: старт контейнера (лимит 3 мин), память при загрузке справочника,
  время на 1000 записей (лимит 5 мин). После первой удачной сборки зафиксируйте версии: `pip freeze`.

## Установка (без Docker)

```
python -m venv .venv
.venv\Scripts\activate        # Windows   (Linux/macOS: source .venv/bin/activate)
pip install -r requirements.txt
```

Нужен Python 3.10+.

## Запуск

1. Из командной строки (проверено):
   ```
   python parse_file.py input.json output.json
   ```
2. Проверка на тестовом наборе (проверено):
   ```
   python dev/run_dev.py          # метрика + расхождения по регрессии
   python dev/run_dev.py --all    # плюс верные записи
   ```
3. API (логика проверена в tests/test_service.py; сам FastAPI не запускался):
   ```
   uvicorn api:app --port 8000
   ```
   `POST /parse` принимает `[{"id","raw_address"}]` (или `{"records": [...]}`) и на каждую запись отдаёт ровно
   один ответ в порядке входа; `POST /parse/explain` добавляет `_sources`, `_flags`, `_suggestions`.
4. Интерфейс (не запускался в среде разработки; «Подсказки справочника» показываются отдельным блоком и в output.json не попадают):


## Как устроено

- `addrparse/parser.py` — очистка, маркеры кв/подъезд/этаж/дом с обеих сторон числа,
  область/город/район, улица/микрорайон/ЖК, ориентир, confidence.
  Два слоя: *extract* берёт только куски строки, *enrich* добивает пустые поля из справочника
  и не перезаписывает найденное в строке.
- `addrparse/refdata.py` — интерфейс справочника. `addrparse/seed.py` — ВРЕМЕННЫЙ маленький набор.
  Настоящий справочник (OSM/КАТО -> SQLite) ещё не подключён.
- `addrparse/metric.py` — метрика жюри (веса 60/25/15, null в эталоне не считается).
- `addrparse/fuzz.py` — rapidfuzz, а если его нет, запасной difflib.

## Известные ограничения

- Без `data/reference.sqlite` используется игрушечный справочник (район и тип улицы подтягиваются только для нескольких улиц).
- Эталон в `dev/dev_set.json` писался вручную тем же автором, что и парсер: 100% на нём не оценка качества.
- Корпус (`5 корпус 2`) попадает в `landmark`.

## Справочник из OSM

Парсер сам подхватывает `data/reference.sqlite` (или файл из переменной `ADDR_REFERENCE`).
Если файла нет, работает мини-справочник `addrparse/seed.py` (только для отладки).

Сборка справочника (нужны osmium, shapely, numpy, ~4 ГБ ОЗУ, 10-25 минут):
```
pip install -r requirements-build.txt
python tools/extract_osm.py kazakhstan-261015.osm.pbf data/reference.sqlite
```
В конце скрипт печатает отчёт (сколько областей/районов/городов найдено, примеры поиска).
Если мало памяти: добавь `--node-cache nodes.cache`.

Разведка файла перед сборкой (необязательно): `python tools/inspect_pbf.py <pbf>` -> `inspect_report.txt`.

Что внутри справочника: области (ручной словарь из 17 областей + 3 города респ. значения),
города/сёла (place=*), районы (admin_level 6-7 внутри казахстанских областей), улицы
(highway + addr:street зданий) и микрорайоны, для каждой улицы город и доля адресов по районам.
Район подставляется в ответ, только если на одном районе больше 70% адресов улицы.

Статус: `extract_osm.py` написан по отчёту `inspect_report.txt`, но на реальном PBF ещё не запускался.

## Грязные адреса

Реальные адреса пишут без области и города, латиницей, слитно (`almaty, abaya81 kv19 Magazin Sabina`,
`абай кошеси 81, п19, сабина дукен алматы`). Парсер это учитывает: транслит и «похожие» буквы,
маркеры (кв/п/оф/этаж) с обеих сторон числа, слипшиеся `81кв19`, город в конце строки, шум
(индекс, телефон, домофон), магазин/кафе как `landmark`.

Также понимаются латиница (`45dom`, `qala`, `kv#19`), литеры через слэш (`112/A`), казахский порядок
(`Мәртөк ауылы`, `ақтөбе облысы`), `***` и `#` в начале/середине, «24 часа» как часть ориентира,
половины двуязычия разной длины (`петропавл/петропавловск`). Слэш НЕ заменяется пробелом: иначе
пропадут дроби (`8/1`, `55/6`). Если в строке есть и город, и одноимённое село (`Ауэзов`, `Астана`),
выбирается город крупнее.

Если города в строке нет (`Абайская улица 81`), поле `city` остаётся пустым: улица с таким названием
есть во многих городах, и подставлять самый крупный мы не вправе. Вместо этого в `/parse/explain`
в `_suggestions.city` приходит список городов, где такая улица есть (по числу адресов в OSM), а
в `_flags` стоит `city_suggested`. UI может показать это как «предположительно Алматы».

Генератор грязных адресов для регрессии (шум придуман автором парсера, это НЕ оценка на скрытом наборе):
```
python dev/gen_noisy.py -n 30 -s 1 --show       # посмотреть примеры
```
